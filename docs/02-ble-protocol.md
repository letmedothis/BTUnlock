# 02 · BLE 广播协议

两端共享实现：`src/BTUnlock.Protocol`。修改任何字段必须两端同步发版。

## 广播参数

| 项 | 值 | 说明 |
|---|---|---|
| 广播类型 | 非连接广播（non-connectable） | PC 只扫描不连接，手机无需维持 GATT |
| 广播间隔 | AdvertiseModeBalanced ≈ 250ms | 响应速度与功耗折中；解锁延迟 ≈ 驻留时间 + 2~3 帧 |
| Tx 功率 | High | 拉远有效距离，让「离开」判定更早触发 |
| Service UUID | `4254554E-4C4F-434B-8E2D-C50F3F1A0001` | 前 8 位十六进制即 ASCII "BTUNLOCK" |
| Manufacturer Company ID | `0xFFFF` | 蓝牙 SIG 测试保留值，自用项目不注册正式 ID |

## Manufacturer Data 负载（12 字节，大端）

| 偏移 | 长度 | 字段 | 值/含义 |
|---|---|---|---|
| 0 | 2 | Magic | `0x4255`（ASCII "BU"），二次过滤误用 0xFFFF 的无关设备 |
| 2 | 1 | Version | `0x01` |
| 3 | 8 | DeviceId | 手机首次安装时 CSPRNG 随机生成，持久化不变 |
| 11 | 1 | Flags | bit0：预留给 M3 滚动令牌开关；其余保留 0 |

## 设备识别与绑定

- PC 端「扫描到的手机」列出所有解析成功的广播 → 用户选中绑定 → 只保存
  DeviceId（16 位十六进制）到配置。
- 手机端界面显示**配对码** = DeviceId 前 2 字节（4 位十六进制），供绑定瞬间
  肉眼比对，防止绑到别人的设备上。

## 设计取舍

1. **为什么不用 GATT 连接读 RSSI**：连接态 RSSI 更稳，但需要维持连接、断连重连
   状态机，且 MIUI 后台限制下更容易断；纯广播 + 前台服务在小米上实测更省心。
2. **为什么 CompanyId 用 0xFFFF**：注册正式 ID 需要蓝牙 SIG 会员；0xFFFF 是测试
   保留值，冲突概率极低且魔数兜底。
3. **静态 ID 的风险**：抓包可克隆。当前只保护「锁屏」动作，风险可接受；
   解锁必须有认证升级（见下）。

## M3 预留：滚动令牌（未实现）

解锁上线前协议升级为：Flags.bit0=1，负载追加 4 字节计数器，密钥 =
HKDF(DeviceId ‖ 配对时协商的 secret)。PC 只信任计数器单调递增的帧，
中继/重放旧帧无法解锁。协议版本号自增，旧版本帧 PC 端仅用于锁屏判定。
