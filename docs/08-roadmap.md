## 1. 指导书的停/继续标准 → 本项目 G0 关卡

指导书 §0：在实机证明「已登录 MSA → 锁屏 → 自定义 CP 用正确 MSA 密码成功解锁」之前，不投入后续集成开发。本项目对应 **G0 关卡（§5）**：解锁组件已随 CI 产出（M3），但**从未装机实测**。G0 是当前最高优先级，且是用户可立即执行的动作。

G0 结果决定分叉：

| 结果 | 后续路线 |
|---|---|
| PASS（MSA 密码自动解锁成功） | 继续 M5 → M6 → M7 评估 → M8 → M9 |
| PARTIAL（本地账户成功、MSA 失败） | 产品定位收敛为「本地账户静默解锁，MSA 明示不支持」，继续 M5/M6/M8/M9 |
| FAIL（全部失败或登录方式被策略禁用） | CP 路线终止，产品降级为「离开锁屏 + 返回后手动验证」；仅保留 M5 的锁意图记录价值、M6 的锁屏侧加固、M9 的验收 |

## 4. 工作节奏

- **G0（用户执行）立即可做**，与 M5/M6 编码并行——这两项是锁屏链路的安全加固，无论 G0 结果如何都有价值。
- G0 出结果后：PASS/PARTIAL → M7 评估、M8、M9；FAIL → M7/M8 取消，M9 只验收锁屏链路。
- 每个里程碑独立小步提交，push 走 Actions 验证（AGENTS.md）；里程碑完成的判据 = CI 绿 + 对应验收矩阵行实机通过。

## 5. G0 关卡：CP 实机 MSA 解锁验证（用户执行，使用 CI 产物）

1. **前置检查**（最快失败点）：设置 > 账户 > 登录选项，确认 Microsoft 账户**密码登录方式可用**。若已启用「仅允许 Windows Hello 登录」，密码路径被策略禁用，G0 直接按 FAIL 收档（可先关闭该策略做一次验证，但不把关闭安全功能当产品前提——指导书 §2.1）。
2. **安全准备**：确认 BitLocker 恢复密钥已备份；创建系统还原点；优先在 VM 或备用机测（指导书 §6.4）；确认原生登录方式（PIN/密码/Hello）当前可用。
3. **安装**：Release 下载 `BTUnlock-UnlockProvider-win-x64-v*.zip`，管理员 PowerShell 执行 `./install-cp.ps1`；确认注册表开关 `HKLM\SOFTWARE\BTUnlock\UnlockProviderEnabled=1`。
4. **录入凭据**：主界面「录入 / 管理密码…」。用户名/域按顺序实测（指导书 §2.1：MSA 的序列化形式是待验证约定）：
   a. `whoami` 显示的本机形式（机器名\用户名）；
   b. `MicrosoftAccount\邮箱` 形式；
   c. 仅邮箱 + 空域。
5. **触发**：开启「人来解锁」→ `Win+L` 锁屏 → 停留 ≥ 5 秒（CP 管道轮询 1.2s）→ 观察是否自动提交并解锁；是否出现额外「登录」按钮（speed bump，指导书 §2.2）。
6. **记录**：Windows 版本号（winver）、账户类型、每种用户名形式的结果、`%ProgramData%\BTUnlock\cp.log`、是否需要额外点击。
7. **失败恢复演练**（必做）：`reg add HKLM\SOFTWARE\BTUnlock /v UnlockProviderEnabled /t REG_DWORD /d 0 /f` 立即停用；`./uninstall-cp.ps1` 反注册；确认原生登录始终可用。

## 6. 里程碑

### M5 · 手动锁屏保护 ✅（2026-11-21 落地，CI Run 19 绿，对齐指导书 §5）

1. `WorkStationLocker` 增加 `TryLockWithIntent(reason)`：调用 `LockWorkStation()` **之前**写锁意图（内存 + 落盘 journal，带过期时间，如 10 分钟），拿到新的 `lock_epoch`。
2. 会话事件监听：`SystemEvents.SessionSwitch`（仓库已有先例 `BluetoothConnectionProbe.cs:177`），处理 `SessionLock` / `SessionUnlock`。
3. 状态机新增两态：`SessionLock` 与未过期锁意图匹配 → `AUTO_LOCKED`；无匹配 → `MANUAL_LOCKED`（宁可不自动解锁，指导书 §5.2）。
4. `UnlockPipeServer._canUnlock` 追加条件「当前状态 == AUTO_LOCKED」（管道协议 Q→A/P 不变，语义收紧）。
5. `MANUAL_LOCKED` 只有收到 `SessionUnlock`（用户人工登录）后才重新武装自动解锁。
6. 崩溃恢复：意图 journal 落盘；重启后能匹配仍在有效期内的意图，匹配不上按 MANUAL_LOCKED。
- 验收：矩阵行 3、4、5。

### M6 · fail-closed 加固 ✅（2026-11-21 落地，对齐指导书 §0 / §6.2）

1. 解锁前置强制：密钥未配置 → `canUnlock` 恒 false（差距 #2）。
2. 令牌新鲜度：最近 N 秒存在通过校验的采样才可解锁。
3. `ProximityDetector`：丢失超时后进入 Unknown，不再评估旧平滑 RSSI；恢复在场必须有新采样（差距 #3）。
4. ~~逐帧去重~~ **修订（2026-11-21 实现时发现）**：广播负载每 10 秒才重建、期间逐帧重复，按内容去重无法区分「设备重发」与「重放」，会丢掉正常采样——不可行。改为收紧新鲜度窗口 ±45s → ±20s（`ProtocolConstants.TokenFreshnessSeconds`），重放假在场上限随之收窄；残余风险在 docs/09 明示。
5. 令牌密钥迁移到 DPAPI CurrentUser 加密存储，settings.json 只留非敏感配置（差距 #5）。
6. 解锁失败熔断：扩展管道协议，CP 在 `ReportResult` 失败时上报 → 连续 3 次失败自动停用 + 托盘提示，人工登录后重录（差距 #6）。
- 验收：矩阵行 6、7、8、10、16。

### M7 · 挑战应答升级（评估项，对齐指导书 §4.2）

- 方向：绑定时交换公钥（Android Keystore P-256，`SHA256withECDSA`，不可导出）；靠近时 PC 作为中心发起 GATT 连接下发 nonce，手机签名、PC 验签（ECDsa/CNG）。
- 收益：nonce 一次性免疫重放、去掉 PC 侧共享密钥、消息可绑会话/SID。
- 成本/风险：Android `BluetoothGattServer` 熄屏存活需按指导书 §7.2 实测；广播 31 字节限制不受影响（挑战走 GATT）；两端各中等代码量。
- 决策点：若 M5/M6 后用户接受残余风险（窗口内重放已挡、中继仍在），可长期保留滚动令牌方案，在文档/UI 明示；否则排入 M7。
- **评估结论（2026-11-21，建议不实施，最终由用户拍板）**：
  1. M6 后挑战应答能消除的窗口内重放已被 ±20s 时间窗近似覆盖，非对称化的边际收益小；
  2. 指导书 §4.2 明确挑战应答防不了中继——其最大理论优势对本项目无效；
  3. 代价：两端新增 GATT server/client 与绑定流程、熄屏 GATT 存活需逐机型实测（指导书 §7.2）、显著扩大代码面；
  4. 单人自用、密钥只在两端本地，撤销能力已足够快（解绑 / 清密钥 / 熔断）。
  **重开 M7 的触发条件**：公开发布或多用户场景、需要把解锁授权绑定到具体用户 SID/会话、或撤销粒度要细到单台手机。

### M8 · 凭据存储升级 ✅（2026-11-21 落地，对齐指导书 §6.3）

1. credential.json 机器级 DPAPI → 用户级 DPAPI（CurrentUser scope），ACL 同步收紧到录入用户。
2. 迁移策略：升级后首次使用要求重录密码（低频操作，简单可靠）。
3. 与 M6.6 联动：密码变更 → 熔断 → 人工登录后重录。

### M9 · 验收矩阵实测 + 威胁模型 ✐（威胁模型已落地 docs/09；矩阵实测待 G0，对齐指导书 §10 / §12）

1. 按 §8 矩阵逐行实机记录（用户执行，CI 产物）。
2. 新增 `docs/09-threat-model.md`：资产、信任边界、STRIDE 摘要、中继攻击与「手机被偷」风险的明确告知话术（指导书 §4.2 两个风险框）。
3. 监测指标（指导书 §10.1 裁剪）：误锁次数/日、**误解锁（恒为 0）**、息屏 1 小时存活率、锁→解锁 P95 耗时、CP 登录失败率。

## 9. 明确不做的事（对齐指导书 §0）

- 不绕过 Windows 认证，不打补丁 / 不注入 `winlogon.exe` / `lsass.exe`。
- 不把 Windows Hello PIN 当作账户密码；不明文保存密码（M6.5 一并修掉令牌密钥明文问题）。
- 不只凭蓝牙 MAC、广播名或单次 RSSI 解锁。
- 不做重启后登录界面、注销后、首次开机登录、RDP、其他用户会话的自动解锁。
- 不禁用系统自带凭据提供程序，不修改系统安全策略来强行解锁。
